# Decision Bootcamp Pilot

A pilot at turning this book into a taught cohort, rather than only a
solitary read — eight sessions, one running decision brief, one capstone
that produces an honest presence/absence check instead of a grade.

This directory is the curriculum's *source*. The student handout and
facilitator guide are build artifacts, generated by
[cohort-kit](https://github.com/alpibrusl/cohort-kit) and never committed
— see `../.gitignore`.

## Files

- **`cohort.yaml`** — identity and format: title, session count, cohort
  size, prerequisite.
- **`sessions.yaml`** — the eight sessions: which chapters each draws on,
  what happens live, the exercise or (session 8 only) the capstone
  deliverable, and the checkpoint that tells you it landed.
- **`rubric.yaml`** — the four dimensions the capstone is actually judged
  on, drawn from Chapter 15's own criteria and the `verify-decision`
  skill's own rule about never resolving a soundness question yourself.
  Shown to students from the start, in the handout itself — not held back
  as a surprise.
- **`fixture/`** — the generated decision brief reused across Sessions 2,
  3, and 5. See `fixture/README.md`.

## Why this curriculum has no code fixture

*Prompt to Decision* is not a hands-on-with-code book the way *Prompt to
Production* is — its exercises are about reasoning and framing a real
decision, not verifying an artifact. So the shared fixture here isn't a
seeded repo; it's a decision brief — a short, generated document laying
out a Ledgerly decision the way one would actually arrive: confident,
well-organized, and quietly missing most of what this book asks a reader
to check before treating it as a decision. Some sessions (1, 4, 6, 7) use
no shared fixture at all — they ask students to apply that session's
framework to a real decision they're actually facing, which is a better
fit for a book whose whole subject is judgement, not verification.

## Build it

```bash
pip install "content-kit-core @ git+https://github.com/alpibrusl/content-kit@main#subdirectory=packages/core"
pip install "cohortkit @ git+https://github.com/alpibrusl/cohort-kit@main"

make cohort-check   # validate sessions.yaml against this book's actual chapters
make cohort-build   # → cohort/build/handout.html, cohort/build/facilitator-guide.html
```

`cohort-check` cross-references every session's chapter list against
`book.yaml` — a chapter renumber in the manuscript surfaces here as a
real check failure, not a stale reference nobody notices.

`cohort-build` passes `--book-path .`, so each session's referenced
chapters are embedded straight from this book's own Markdown — collapsed,
one per chapter, right where that session lists them. A student needs
nothing but the handout itself to read along; no PDF or EPUB has to exist
first, and the book's own text never drifts out of sync with the source.

## The capstone

Session 8 has no `exercise` — it sets a `deliverable` instead. Each
student runs this repo's own `skills/verify-decision` skill against a
real recommendation (their own if one is actually in flight, the fixture's
decision brief if not) and presents the result: what was actually stated
versus only assumed, using the skill's own Found / Not found / Ambiguous
distinctions, and which soundness questions still need a specific named
human's answer. The rubric grades the check, not the underlying decision —
a student who honestly reports a pile of gaps has done the assignment
correctly; one who quietly fills a gap in with a plausible-sounding answer
has done the exact thing the skill's own rules forbid.

## Status

Pilot. Not yet run with a real cohort. If it holds up, the same shape —
a decision brief instead of a code fixture, recurring sessions, a
skill-run capstone — is the template the other three books in the series now follow for
their own cohorts.
